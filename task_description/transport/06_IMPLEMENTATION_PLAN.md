## Рекомендований порядок продовження (на 2026-08-24)

1. **Фаза 14 → Фаза 16 фронтенду** (`RequireRole` → `FleetList`) —
   найактуальніше: без цього щойно зроблений редірект Mini App за
   роллю (2026-08-19) веде адміна/логіста в порожню заглушку.
2. **Дозаповнити `IMPORT_1C_SPEC.md`** (відповіді користувача) →
   дописати Крок 11 бекенду (`DJANGO_CODING_GUIDE.md`) → тільки тоді
   писати upload-форму `/waybills/import` на фронтенді.
3. **Крок 12-13 "Що далі"** (`HiredTripForm`/`CarrierShipmentForm`) —
   бекенд уже готовий (Фаза 11), можна брати в будь-який момент після
   пункту 1.
4. **`apps.analytics` + Крок 14 "Що далі"** — після того, як у БД
   накопичиться реальна історія (не раніше).
5. **Крок 15 "Що далі"** (адмін-панель) — вимагає окремого backend-
   кроку (`pending-users` ендпоінти), ще не описаного в жодному гайді.

## Первинний план (архів, орієнтир задуму — НЕ хід виконання)

Спочатку планувалось: React SPA на mock JSON без бекенду (5 тижнів,
"Тиждень 1 — Foundation" ... "Тиждень 5 — Аналітика + PWA"), backend
Django+DRF — "майбутній, поза scope MVP". Насправді бекенд писався
паралельно й випередив фронтенд — Фази вище це відображають. Деталі
початкового тижневого плану звідси прибрано як такі, що вводять в
оману щодо реального ходу роботи; якщо потрібен історичний контекст —
дивись git-історію цього файлу.
